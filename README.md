# Десять дней в доме Грейстоуна

Нарративная детективная HTML-игра о возвращении Леонарда Грейстоуна в родовое имение, расследовании внутреннего заговора и выборе будущего дома.

## Концепция

**1896 год.** До приезда невесты Леонарда, Эвелин Хартвелл, остаётся десять дней. За это время игрок должен восстановить контроль над имением, раскрыть семейное прошлое и определить, кто из шести горничных готовит преступное действие.

При начале новой игры виновница выбирается из шести вариантов. Вместе с ней меняются мотив, метод, ложные следы, серьёзный инцидент, финальный план и персональная концовка.

## Технологический стек

Проект реализуется как статическое веб-приложение:

- HTML5;
- CSS3;
- JavaScript ES Modules;
- JSON для нарративных данных;
- LocalStorage для прототипа сохранений;
- без обязательного фреймворка на первом этапе.

Для запуска нужен локальный HTTP-сервер, так как браузеры ограничивают загрузку ES-модулей и JSON через `file://`.

Пример:

```bash
python -m http.server 8000
```

После этого открыть `http://localhost:8000`.

## Канонический источник

Основой проекта является Google-таблица:

[«Десять дней в доме Грейстоуна — полная структура квеста»](https://docs.google.com/spreadsheets/d/1HA5h-c23Fh7f6mlenUpuVSNdyLunEsK_E1GfPU3drB8/edit)

Для разработки используются листы с суффиксом **`_редакция_1`**. Они содержат:

- 10 игровых дней;
- 6 преступных версий;
- 30 версионных улик;
- 32 системных события;
- 3 финальные стратегии;
- 18 успешных QA-маршрутов;
- персонажей, отношения, расписания, предметы и личные линии;
- диалоговые узлы и визуальные переключения;
- 258 запланированных графических ассетов.

Диалоги могут обновляться параллельно: движок должен получать их из JSON, а не хранить реплики внутри компонентов интерфейса.

## Стабильные ID

- `portrait_` и `bg_` — графические состояния;
- `item_` — предметы;
- `poi_` — точки поиска;
- `clue_` — улики;
- `scene_` — сцены;
- `event_` — события;
- `arc_` — личные и сюжетные линии;
- `flag_` — булевы состояния;
- `state` — типизированные значения игрового состояния.

ID из таблицы не следует переименовывать вручную. Манифест связывает ID с реальным путём файла.

## Основные системы

1. Десятидневный календарь и 5 ОД в день.
2. Перемещения, расходующие время, но не ОД.
3. Динамические расписания NPC.
4. Диспетчер обязательных и условных событий.
5. Диалоговые узлы, выборы, отношения и смена портретов.
6. Предметы, точки поиска и журнал улик.
7. Доказательное ядро: возможность, умысел и связь с финальным действием.
8. Три стратегии финала: официальное разбирательство, засада, запирание дома.
9. Единый resolver четырёхслойной концовки.
