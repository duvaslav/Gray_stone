# Архитектура HTML-игры

## Принцип

Проект строится как статическое веб-приложение без обязательного фреймворка. HTML отвечает за точку входа, CSS — за визуальный слой, ES-модули JavaScript — за движок и интерфейс, JSON — за нарративные данные.

## Слои

```text
src/
├── js/
│   ├── app.js            # запуск приложения
│   ├── core/             # состояние, события, условия, сохранения
│   ├── systems/          # время, ОД, улики, отношения, финалы
│   ├── screens/          # титульный экран, карта, диалог, журнал
│   ├── ui/               # переиспользуемые компоненты
│   └── utils/            # общие функции
├── data/                 # JSON, импортированный из таблицы
├── styles/               # базовые стили, экраны, компоненты
└── locales/              # текст интерфейса
```

## Единственный источник истины

- сюжет и системные правила: Google Sheets `_редакция_1`;
- исполняемая копия: `src/data/*.json`;
- реальные пути изображений: `src/data/assets.manifest.json`;
- код не должен переопределять канонические ID.

## Игровое состояние

Сохранение содержит только изменяемые значения: день, время, ОД, локацию, виновницу, отношения, флаги, предметы, улики, завершённые события и историю диалогов. Статические описания остаются в JSON.

## Порядок разработки

1. Импорт справочников и ID.
2. Валидатор ссылок.
3. Карта и время.
4. Диспетчер событий.
5. Диалоговый экран.
6. Улики и журнал.
7. Финальные стратегии и resolver.
8. Полные QA-маршруты.
